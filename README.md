# 부산 공영주차장 통합 검색

HTML / CSS / JavaScript와 Cloudflare Pages Functions만 사용하는 버전입니다.

## 배포
기존 저장소의 index.html, style.css, script.js, functions/api/parking.js를 이 파일로 교체합니다.
Cloudflare Pages 운영 환경에 Secret SERVICE_KEY를 등록합니다. 인증키는 코드나 Git에 넣지 않습니다.
두 서비스(부산광역시 공영주차장 정보, 부산시설공단 주차장 정보)의 활용 승인이 필요합니다.
커밋하고 push하면 기존 GitHub 연동 배포가 실행됩니다.

커밋 메시지: feat: 공영주차장 통합 검색 및 실시간 현황 표시

## 기능
- 부산 공영주차장 기본 목록과 시설공단 목록/실시간 현황을 통합
- 모든 API 페이지를 조회하고 전체 목록에서 이름/주소 검색
- 검색 결과는 30개씩 더 보기 (검색 자체는 전체 대상)
- 기본요금, 운영시간, 주차면수, 상세정보
- 유효한 실시간 수치만 표시하고 미제공/조회 불가를 구분
- 일부 API 실패 시 정상 API 정보 표시와 경고
- 새로고침 버튼으로 현황 갱신; 자동 주기 갱신은 없음
- 카카오맵 검색결과 바로가기 제공 (지도 API·SDK 미사용)

## 데이터 연결의 한계
기본 API의 mgntNum과 시설공단의 parkgcd는 다른 식별자입니다.
공백 및 공영/주차장 표현을 제거한 이름이 양쪽에서 유일한 경우만 연결합니다.
이름이 다르거나 중복된 경우 잘못 연결하지 않도록 별도 항목으로 유지합니다.
정확한 전체 중복 제거에는 검증된 수동 매핑이 필요합니다.
실시간 정보만 있는 주차장은 주소/요금/운영시간 정보 없음으로 표시됩니다.
원본의 잘못된 시간(예: 00:80)은 '제공 시간 확인 필요'로 표시합니다.
0원 요금은 원본 값을 표시하며 무료로 단정하지 않습니다.

## 검증
모의 API 응답으로 전체 페이지 조회, 실시간 매칭, 0/빈 값/비정상 값, 일부 API 실패를 확인했습니다.
실제 인증키를 사용한 운영 API 호출 및 Cloudflare 배포는 별도 확인이 필요합니다.

## 이번 수정
실시간 현황 정상 제공 → 실시간 제공 대상이나 조회 불가 → 일반 주차장 순으로 정렬합니다.
주소는 도로명 → 지번 순으로 표시합니다. 양쪽 API 명칭의 공백·쉼표·괄호 표기 차이를 정리하고 목록/현황의 두 이름을 확인합니다. 구역 번호와 남측/북측은 보존합니다.
주소 누락은 기본 API 조회 실패 / 이름 연결 실패 / 원본 미제공으로 구분합니다. 이름 자체가 다른 주차장은 정확한 주소 연결에 추가 검증된 매핑이 필요합니다.

## 상세정보 표시 수정
- 같은 이름·같은 주소의 기본 항목이 여러 개일 때 서로 일치하는 상세 항목을 보완합니다.
- 충돌하는 값은 임의로 선택하지 않으며 시간과 요금은 쌍으로 비교합니다.

- 명칭이 완전히 다른 주차장은 별도 검증된 매핑이 필요하므로 상세정보가 없는 항목이 남을 수 있습니다.

## 카카오맵 및 화면 개선
카카오맵은 https://map.kakao.com/link/search/ 의 검색결과 바로가기 방식입니다.
각 카드에서 새 창으로 열며 검색어는 부산 + 주차장명만 사용합니다. 공공데이터 주소는 지도 검색어에 넣지 않습니다.
카카오 앱 키나 도메인 등록은 필요하지 않습니다. 지도 자체는 현재 페이지에 삽입하지 않습니다.
주소는 원본을 유지하고 '주소(공공데이터 기준)' 및 실제 위치와 다를 수 있다는 안내를 표시합니다.
상세정보의 요금 안내·특이사항·결제 방법 항목은 화면에서 제외합니다. 기본·추가·일·월 요금은 유지합니다.
밝은 배경, 청록색 검색 버튼, 정돈된 카드와 모바일 레이아웃을 적용합니다.
이번 화면 변경 파일: index.html, script.js, style.css. functions/api/parking.js에는 직전 상세정보 수정이 포함되어 있습니다.

## V5 PWA 설치 기능

기존 웹 화면에 홈 화면 설치 기능을 추가했습니다. 문서 예시의 app.js 대신 실제 script.js를 사용하고 기존 청록색 디자인을 유지합니다.

### 적용할 파일
- 교체: index.html, style.css, script.js, README.md
- 추가: pwa.js, manifest.webmanifest, service-worker.js, icon-192.png, icon-512.png
- functions/api/parking.js는 이번 작업에서 변경하지 않았습니다.
모든 추가 파일은 index.html과 같은 저장소 루트에 둡니다. 별도 패키지 설치나 빌드 설정 변경은 필요 없습니다.
SERVICE_KEY 설정은 기존 Cloudflare Secret을 그대로 사용합니다.

### 설치
- HTTPS 운영 사이트에서 Chrome/Edge 등 설치 이벤트를 지원하는 브라우저가 설치 가능하다고 판단하면 ‘앱처럼 설치하기’ 버튼이 표시됩니다. 모든 접속에서 버튼 표시를 보장하지는 않습니다.
- iPhone/iPad에는 Safari 공유 메뉴 → ‘홈 화면에 추가’ 안내를 표시합니다.
- 설치된 앱의 독립 실행 화면에서는 설치 안내를 숨깁니다.
- 아이콘은 P / BUSAN이며 설치 후 독립 화면(standalone)으로 실행합니다.

### 캐시와 실시간 정보
- 정적 파일만 설치 시 캐시하며, 온라인에서는 네트워크를 우선 사용합니다.
- /api/ 하위 요청과 외부 카카오맵 링크는 Service Worker에서 처리하거나 캐시하지 않습니다.
- /api/parking 요청은 fetch의 no-store 옵션도 적용합니다. 서버의 기존 Cache-Control: no-store도 유지됩니다.
- 오프라인에서는 캐시된 화면만 열 수 있습니다. 주차장 목록·실시간 정보는 오프라인 저장하지 않습니다.
- 화면이 열린 상태에서 조회 실패 시 기존 메모리의 결과가 남을 수 있으므로 이전 정보 경고를 표시합니다. 연결 복구 후 ‘정보 새로고침’으로 다시 조회합니다.
- 정적 파일 변경 시 service-worker.js의 CACHE_NAME 버전을 올려 새 캐시를 만듭니다. 이전 앱 버전의 열린 탭/앱을 모두 닫고 다시 접속하면 대기 중인 새 Worker가 활성화되고 이전 정적 캐시가 정리됩니다.
- 강제 skipWaiting이나 자동 새로고침은 사용하지 않습니다.

### 배포 후 확인
1. GitHub에 커밋·푸시한 후 Cloudflare의 운영 배포 커밋이 해당 커밋인지 확인합니다.
2. 기본 운영 주소에서 manifest와 아이콘, service-worker.js가 200 응답인지 확인합니다.
3. 개발자 도구 Application에서 Manifest, Service Worker 등록, 정적 Cache Storage를 확인합니다. API 응답은 캐시에 없어야 합니다.
4. PC/Android에서 설치, P / BUSAN 아이콘, 독립 실행을 확인합니다. iPhone은 Safari 홈 화면 추가를 확인합니다.
5. 한 번 온라인 접속 후 오프라인 재접속 시 화면과 연결 안내가 뜨는지 확인합니다. 실시간 수치가 새로 제공되는 것으로 표시되면 안 됩니다.
6. 다시 온라인으로 연결하고 정보 새로고침 시 /api/parking 네트워크 요청을 확인합니다.
